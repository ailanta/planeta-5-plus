## 1. Целевой результат

Красивый иллюстрированный город для ребёнка 9–12 лет: объёмные стеклянные здания, тёплый свет в окнах, зелёные террасы, воздушная перспектива, небо и мягкий солнечный свет. Ориентир — приложенный пользователем коллаж Image #1, а особенно его первые три панели: городской масштаб, фактура фасадов, свет и белые читаемые карточки поверх мира.

Референс на момент составления плана: `C:/Users/trety/Downloads/ChatGPT Image 12 сент. 2026 г., 16_38_36.png`. Перед работой с графикой сохранить копию в `design/references/city-reference.png`, если источник доступен; не делать приложение зависимым от Downloads. Если источник недоступен следующему агенту, использовать описание этого документа и запросить повторное вложение только для точного визуального сравнения.

Каждая учебная тема получает свой участок улицы и собственное здание. Русский язык — район города; «Проверяемые гласные», «Парные согласные», «Части речи» — разные здания. Не путать учебную тему с предметом. У других предметов впоследствии могут быть свои районы или миры; в первый срез они не входят.

Улица прокручивается пальцем вправо-влево между зданиями и вверх-вниз вдоль их высоты. Камера не вращается. Объём существует в рисунке: виден фасад, одна боковая грань, толщина перекрытий, блики и тени. На экране задания камера приближается к выбранному зданию, вопрос размещается перед ним, а городской фон остаётся виден.

Не переносить из коллажа педагогические ошибки: «этаж потерян», разрушение готовой башни, штрафы и сомнительные примеры слов. Ошибка означает ремонт текущего модуля. Достижение высоты и устойчивое освоение темы — разные события.

## 2. Решение по графике

Использовать 2D-композицию HTML/CSS + растровые изображения с прозрачностью; SVG — для интерфейсных значков, рамок, контуров ремонта и простых эффектов. React управляет состоянием, CSS — перемещениями и затуханиями. Для первой версии WebGL и игровой движок не требуются.

Объёмный художественный результат определяется качеством исходных иллюстраций. Добавление градиента к прямоугольникам текущего SVG-прототипа не является завершением этого редизайна.

### Комплект одного здания

| Элемент | Количество для первого здания | Назначение |
|---|---:|---|
| Основание и вход | 1 | связь с тротуаром, двери, масштаб |
| Обычный этаж | 3 варианта | стекло, бетон, разные окна без изменения стыков |
| Секция ×2 | 1, высотой в 2 обычных этажа | панорамное остекление, зелёная терраса |
| Секция ×3 | 1, высотой в 3 обычных этажа | выразительная галерея или зимний сад |
| Строительная верхушка | 1 | незавершённая башня, крепление груза |
| Завершённая крыша | 1 | фонарь/купол, итог строительства |
| Накладка ремонта | 2 | трещина на текущем модуле; леса для повторения |
| Подсветка успеха | 1 или процедурный SVG | короткий световой контур нового модуля |
| Превью здания | 1 | карточка темы и дешёвое отображение вдали |

Один ×2-ответ добавляет двухэтажную секцию, один ×3 — трёхэтажную. Это сохраняет награду 1/2/3 и делает сложность видимой. Не выдавать декоративный VIP-этаж только из-за его порядкового номера.

Не нужны 50 отдельных картинок для 50 этажей. Обычные этажи переиспользуются с детерминированным выбором варианта; особые секции добавляются по истории наград. Для второго здания нужен собственный набор с тем же техническим контрактом: например, светлая башня с вертикальными рёбрами вместо синего стеклянного фасада.

### Как избежать швов и «кривой башни»

1. Сначала создать цельную мастер-иллюстрацию здания и технический чертёж модулей.
2. Зафиксировать слабую перспективу/почти параллельную проекцию, одну видимую боковую грань и один источник света сверху слева. Сильное перспективное сужение несовместимо с неограниченным повторением одного этажа.
3. Подготовить секции на общем холсте; координаты боковой грани и границ перекрытия одинаковы у всех вариантов.
4. Генерировать варианты редактированием общей основы. После генерации обязательно выровнять и очистить края в графическом редакторе. Результат генератора не считать готовым игровым ресурсом.
5. Проверить сборку 1/5/12/30/50 этажей на светлом и тёмном фоне, включая произвольное соседство обычной, ×2 и ×3 секций.
6. Если перспективные швы не удаётся убрать, упростить проекцию. Запасной вариант для обзора улицы — цельные изображения стадий роста; в приближённой сцене сохранить модульную сборку.

Все модульные изображения: прозрачный фон, без текста, чисел, неба, земли, соседних зданий и глобальной падающей тени. Локальные тени от перекрытий допустимы. Тень всего здания — отдельный слой.

## 3. Контракт ресурсов

Рабочий шаблон первого набора: ширина холста 768 px, обычный этаж 128 px полезной высоты. Секция ×2 — 256 px, ×3 — 384 px полезной высоты. Дополнительные прозрачные поля и выступы описываются явно; размеры уточнить в техническом арт-тесте до массового производства.

В manifest каждого ресурса хранить:

```ts
type BuildingAsset = {
  id: string
  src: string
  fallbackSrc?: string
  width: number
  height: number
  anchor: { x: number; y: number } // пиксели: точка привязки нижнего стыка
  stackHeight: number             // шаг сборки, без прозрачных полей
  visualBounds: { x: number; y: number; width: number; height: number }
  floorUnits: 0 | 1 | 2 | 3
  kind: 'base' | 'standard' | 'x2' | 'x3' | 'roof' | 'construction' | 'repair'
}
```

Нулевые floorUnits — у основания, крыши и накладок. Раскладка считается по stackHeight и anchor, а не по размеру PNG. Сохранять исходники с прозрачностью; в приложение экспортировать оптимизированный WebP, при необходимости PNG-fallback. Формат и масштаб выбирать после визуальной проверки краёв и веса. Имена файлов с версией/хешем. Записать происхождение и условия использования в `design/assets/ASSET_SOURCES.md`.

## 4. Улица и камера

Слои от дальнего к ближнему: небо → далёкий город/река → участки с тематическими зданиями → тротуар/растения/герой → интерфейс. У каждого слоя своя скорость горизонтального движения; фон зацикливается через подготовленный бесшовный стык или отдельные переходные сегменты.

Участок = фиксированное место здания, его тень и доступная кнопка с названием темы. Нажатие выбирает тему; горизонтальный свайп перемещает между участками, вертикальный — к верхним или нижним этажам. Начать с единого ограниченного viewport с нативным overflow по обеим осям и общей плоскостью мира внутри. Панель навигации закреплена вне прокручиваемой плоскости. Не включать обязательный scroll-snap на первом этапе: он не должен перетягивать диагональный жест или мешать осмотру верхних этажей. Декоративный параллакс обновлять через requestAnimationFrame, не через React-state на каждом scroll.

Экран города занимает доступную высоту; вертикальный жест внутри его сцены перемещает камеру, за пределами сцены действует обычная прокрутка интерфейса. Не применять глобальный preventDefault. Дополнительные кнопки «Предыдущая тема»/«Следующая тема», «К вершине» и «К основанию» позволяют обойтись без жестов; поддержать клавиатуру. Перемещение камеры по высоте и направлению пальца следует обычной модели прокрутки содержимого.

Начальная позиция — основание выбранного здания. При продолжении строительства камера переходит к рабочему этажу. Верхняя граница мира определяется самым высоким зданием плюс запас под крышу и облака, нижняя — улицей. Вверх можно подняться только в пределах существующего мира, без бесконечного пустого неба. При ручном переходе между зданиями сохранять высоту камеры; если низкое здание осталось внизу, показывать понятную кнопку «К зданию». При явном выборе темы центрировать её видимую часть.

Видимы выбранный участок и части соседних. Подробно рисовать только выбранное здание и ближайших соседей, а также этажи в вертикальной области видимости с небольшим запасом; остальные — лёгкими превью или заглушками той же геометрии. При возвращении из задания восстановить выбранную тему и обе координаты обзора камеры.

В режиме задания улица не двигается от жестов по карточке. Камера показывает верх строящегося здания с запасом под анимацию и плавно поднимается после монтажа новой секции. Готовые нижние этажи уходят за экран, а не сжимаются до полосок. Кнопка «Осмотреть башню» временно сворачивает карточку и разрешает вертикальный обзор; «К заданию» восстанавливает рабочую высоту, введённый ответ и состояние подсказок. При открытии обзора не отправлять ответ и не завершать сессию. Общий вид всей башни можно добавить отдельной кнопкой, но основное перемещение по высоте должно сохранять читаемый масштаб этажей.

Переход улица → задание: 350–500 мс. Новая секция: опускание на место + мягкая подсветка за 450–700 мс. Эти времена — стартовые параметры. Следующее действие не должно ждать окончания эффекта. При reduced-motion — мгновенная смена позиции и короткое/нулевое затухание.

## 5. Прогресс: отделить образование от архитектуры

Сцена получает нормализованное состояние 0…1 и события, не вычисляет освоение по высоте картинки.

```ts
type WorldProgress = {
  topicId: string
  constructionProgress: number // 0…1, стройка
  masteryStatus: 'learning' | 'review' | 'mastered'
  earnedFloorUnits: number
  modules: Array<{
    id: string
    rewardEventId: string
    sourceExerciseId: string
    kind: 'standard' | 'x2' | 'x3'
    variant: number
    floorUnits: 1 | 2 | 3
  }>
  repairModuleIds: string[]
}
```

Визуальные стадии задаёт тема здания: 0–10% основание; 10–30% нижний город; 30–60% высотка; 60–85% облака; 85–100% вершина. Число этажей не является координатой камеры. Layout должен работать с разными целями, а не только с 12.

Награду выдавать ровно один раз на завершённый учебный эпизод, используя устойчивый eventId; повторный клик или перезагрузка не добавляют секции. Ремонт существующей секции восстанавливает её, не создаёт копию. Правила награды при первом исправлении согласовать с существующим учебным циклом и покрыть доменным тестом.

После заполнения башни практика продолжается. Ближайшая реализация: завершённое здание остаётся, новые ответы показывают «Закреплено», а ремонт восстанавливает связанные модули. Не показывать «+1 этаж», если высота фактически ограничена. Расширение участка/новая башня после завершения — отдельная будущая механика.

Миграция текущего Progress v1: сохранить попытки, навыки и этажи; привязать их к первой теме. Старые этажи допустимо показать обычными: история не содержит надёжного журнала каждого строительного события. Не придумывать, что старый четвёртый этаж был заработан за ×2. Сохранять новые строительные события и связь ремонта с модулем в версии 2; экспорт/импорт должны поддерживать эту миграцию.

## 6. Игровой экран

Небо и фасад занимают фон целиком. Вверху — выход, короткое название темы и прогресс сессии. Задание в светлой непрозрачной карточке с мягкой тенью. Ни блики, ни окна не проходят через буквы. На телефоне карточка находится в нижней части видимого экрана, а верх здания остаётся над ней; на большом экране возможна карточка сбоку от фасада.

×1: инструкция «Вставь пропущенную букву», одно крупное слово, 2–3 кнопки букв. ×2: ясные последовательные шаги написания и проверочного слова. ×3: предложение, выбор ошибки, затем исправление и проверочное. Текст заданий, номера этажей и названия тем всегда HTML, не часть сгенерированной картинки.

Для длинных слов — адаптивный размер без разрыва слова; ориентир 28–40 CSS px. Проверить реальное длинное слово «удивительный». Основные цели нажатия от 44×44 px, кнопки букв предпочтительно от 56 px. Все поля от 16 px, чтобы ввод не провоцировал нежелательное увеличение на iPhone.

При открытой клавиатуре уменьшать/сворачивать декоративную часть, оставлять поля и основную кнопку в доступном вертикальном потоке. Проверять safe-area, короткие экраны и поворот. На 320 px и при увеличении текста допустим вертикальный скролл, но недопустим горизонтальный скролл карточки.

Успех: «+2 этажа. Проверка верна» и монтаж соответствующей секции. Ошибка: «Проверим ещё раз», лёгкая трещина на текущем модуле, доступная подсказка. Никакого обвала, вспышки на весь экран и красного наказания. Ремонт различим формой лесов и текстом, а не только цветом.

Итог освоения: отдаление камеры, здание над облаками, затем доступная карточка результата. Показывать реальные показатели эпизодов, а не вымышленные числа из коллажа; отделять количество заданий от повторных отправок ответа. Анимацию можно пропустить. Построенная башня без устойчивого освоения получает текст «Башня построена. Закрепляем знания».

## 7. Художественное направление и производство

Начать с рисованного города как в референсе: холодное синее стекло, светлый камень, тёплые окна, зелень, сине-фиолетовое небо и лавандовые облака. Верхняя панель тёмно-синяя, карточки молочно-белые, акцент успеха бирюзовый, ремонт розово-коралловый. Кран не является обязательным элементом: силуэт башни и фундамент должны читаться без него.

Герой маленький, с каской и рюкзаком, внизу сцены; достаточно 2–3 поз и короткой реакции. Облака двигаются медленно; дрон появляется редко; фон не конкурирует с чтением. Во время ввода и подсказки можно приостанавливать декоративные эффекты. Не добавлять серии/комбо и бонусные этажи в рамках визуальной задачи: они меняют систему мотивации.

Бриф для генерации мастер-арта: «Вертикальное стеклянное здание в современном солнечном городе, качественная стилизованная объёмная иллюстрация, голубое стекло, светлые перекрытия, тёплые окна, зелёные террасы, спокойная детализированная архитектура для игровой сцены 9–12 лет, фиксированный вид спереди с одной узкой правой гранью, слабая перспектива, освещение сверху слева. Без букв, интерфейса, логотипов и водяных знаков».

Это бриф для художественного поиска, а не гарантия совместимости секций. После мастер-арта нужен технический лист: силуэт, ширина фасада, ширина боковой грани, горизонт стыка, высота секции, прозрачные поля, направление тени. Агент генерации ресурсов обязан использовать его как постоянный референс.

### Первый принятый набор ресурсов

Для первого здания сгенерированы и очищены от шахматного фона три RGBA-спрайта 512 px шириной: `floor-standard-v2.png`, `floor-x2-v2.png`, `floor-x3-v2.png`. Они подключаются и в полной сцене, и в компактном preview с адаптивным масштабом. ## 8. Производительность и офлайн

Рабочие бюджеты, подлежащие измерению на реальном устройстве: первая сцена до 2 МБ сжатой графики; полностью загруженный первый набор до 5 МБ; декодированные активные изображения желательно до 64 МБ; JS сохранять в рамках текущего лёгкого React-приложения. Размер на диске не равен памяти: RGBA-изображение занимает примерно width × height × 4 байта без дополнительных копий.

Фон готовить отдельными мобильными вариантами; не загружать огромную панораму целиком ради одного экрана. Соседние темы подгружать после выбранной. Перед анимацией декодировать нужную секцию; на время загрузки сохранять её геометрию и простой fallback. Анимации ограничить transform/opacity; не запускать React-render для каждого кадра.

Офлайн гарантируется только для успешно загруженных ресурсов: оболочка и первая тема кэшируются первыми, прочие темы — по посещению. При обновлении не удалять работающий набор раньше загрузки нового. Использовать версионированные пути и проверить обновление старой установки. В dev service worker остаётся отключённым. Все игровые ресурсы поставляются с сайтом, без внешних шрифтов и обязательных графических CDN.

## 10. Матрица проверки и готовность

Сделать dev-only галерею сцен с фиксированными данными: пустой участок, 5/12/30/50 этажей, подряд ×2/×3, ошибка, ремонт при полностью построенной башне, успех, завершённая стройка без освоения, освоенная тема, длинное слово, ×3 с длинным предложением. Галерея не изменяет реальный прогресс ребёнка.

Проверить ширины 320/390/430 px и desktop; Safari на реальном iPhone отдельно от Chromium; экранную клавиатуру, поворот, reduced-motion и увеличение текста. Проверить подъём от основания до 50-го этажа и обратно, диагональный жест, переход от высокой башни к низкой на большой высоте, возврат к заданию с заполненным полем, восстановление X/Y после выхода в игру. На каждом ключевом экране сохранить скриншот после окончания загрузки и анимации, а не только DOM-дерево.

Функциональные проверки: награда ×2 действительно монтирует 2 единицы, ×3 — 3; повторное событие не дублирует секцию; ремонт связан с реальным заданием; прогресс не теряется после миграции и reload; после 100% можно тренироваться. При разработке тестировать новые чистые расчёты и опасные переходы данных, не писать тесты на каждый декоративный CSS-класс.

Визуальные проверки: нет швов и ореолов на прозрачных краях; крыша сидит на верхнем стыке; основание касается земли; тени направлены одинаково; башня не выглядит растянутой; незавершённые этажи не образуют уже готовый полный силуэт; текст и органы управления не нарисованы в фоне.

На выбранном iPhone записать модель/версию ОС, время открытия с холодным и тёплым кэшем, объём ресурсов и запись свайпа/монтажа. Цель — плавное движение около 60 fps без заметных остановок; при просадках сначала уменьшать активные слои, размер ресурсов и декоративную анимацию. Проверить offline и обновление приложения без повторения прежнего бага со старым кэшем.

Первый принимаемый результат — один законченный игровой срез с качественным зданием, улицей из активного дома, соседнего фундамента «＋» и двух обозначенных будущих участков, ×1/×2/×3, ошибкой, ремонтом и итогом. Полноценные новые предметы, вращение камеры и множество художественных наборов в этот этап не входят.
